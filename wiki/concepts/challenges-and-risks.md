# 挑戰與風險

## S1 列出的三大限制

1. **Context 長度有限**：放不下所有歷史、指令、工具回應；向量檢索可以補充，但表達能力不如完整的注意力機制 [S1]。
2. **長期規劃與任務拆解困難**：遇到意外錯誤時不太會調整計畫，不像人類能從試錯中學習 [S1]。
3. **自然語言介面不可靠**：模型可能輸出格式錯誤或不照指令做，所以很多 agent 程式碼都在解析模型輸出 [S1]。

## 只推理、不行動的問題

只靠模型內部推理（例如 chain-of-thought）時，容易產生幻覺，而且前面的錯誤會一路傳遞下去；讓模型透過工具查證外部資訊可以減輕這個問題 [S2]。

## 成本與錯誤累積

Agent 的自主性代表成本較高，而且錯誤可能一步步累積（compounding errors）；建議在沙盒環境中大量測試，並加上適當的防護 [S3]。

## 從原型到正式上線的挑戰

S5 指出，agent 的「最後一哩路」常常占了大部分工作 [S5]：

- **有狀態、錯誤會累積**：agent 長時間執行，一個小錯可能讓它走上完全不同的路；出錯時不能每次從頭來，需要能從中斷處繼續 [S5]。
- **難以除錯**：同樣的提示每次結果可能不同，需要完整追蹤 agent 的決策過程 [S5]。
- **部署要小心**：更新時可能有 agent 正執行到一半，需要讓新舊版本同時運行、逐步切換 [S5]。

## 讓 LLM 評自己的風險

ChemCrow 案例中，LLM 評估認為它和 GPT-4 表現差不多，但化學專家評估認為 ChemCrow 明顯較好 → 在需要專業知識的領域，LLM 可能看不出自己的錯，不適合單獨當評審 [S1]。
