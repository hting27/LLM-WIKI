## 閱讀筆記（改寫）

- 定義：agent 是「能代替使用者、相當獨立地完成任務」的系統。
  - 用 LLM 管理工作流程的執行與決策；知道何時完成、能主動修正，失敗時可停下來把控制權交還使用者。
  - 能使用多種工具與外部系統互動（拿資訊、採取行動），並依當下狀態挑選工具，且在清楚的防護欄內運作。
  - **不算 agent**：簡單聊天機器人、單輪 LLM、情緒分類器 —— 因為它們沒有用 LLM 控制工作流程。
- 何時值得做 agent（三個條件，否則用確定性的傳統方案即可）：
  1. 複雜判斷（例：客服退款核准）
  2. 規則多到難以維護（例：供應商資安審查）
  3. 大量非結構化資料（例：處理房屋保險理賠）
  - 比喻：規則引擎像檢查清單；agent 像有經驗的調查員。
- 三個核心元件：**模型**（推理決策）、**工具**（外部函式/API）、**指令**（明確的行為準則與防護）。
- 模型選擇：先用最強的模型建立基準，再試著換成小模型降低成本與延遲。
- 工具三類：資料類（查資料）、行動類（寫入、寄信）、編排類（其他 agent 也可以當工具）。
- 指令：善用既有作業文件、拆成小步驟、每步對應明確動作、預先處理邊界情況。
- 編排（orchestration）：
  - 每個 agent 都需要一個「run」——一個 while 迴圈，直到達成結束條件（呼叫最終輸出工具、沒有再呼叫工具、出錯、或達最大輪數）。
  - 建議**先把單一 agent 能力做到最大**，真的需要才拆成多 agent。拆分時機：條件分支太多、工具重疊造成選錯（有團隊能管好 15 個以上清楚的工具，有團隊不到 10 個重疊工具就出錯）。
  - 多 agent 兩種模式：**Manager**（中央 agent 把其他 agent 當工具呼叫）、**Decentralized**（agent 之間互相 handoff 交接）。多 agent 系統可以建模成圖：agent 是節點，邊是工具呼叫或交接。
- 防護欄（guardrails）：多層防禦 —— 相關性分類器、安全分類器（越獄/提示注入）、個資過濾、內容審核、工具風險分級（低/中/高）、規則式防護（黑名單、長度限制、regex）、輸出驗證。
- 人工介入兩大時機：**超過失敗門檻**（例如重試多次仍不懂使用者意圖）、**高風險行動**（不可逆、金額大，例如取消訂單、大額退款、付款）。
- 結論：從小做起、用真實使用者驗證、逐步擴充能力。
