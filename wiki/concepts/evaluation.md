# 怎麼評估一個 Agent？

## 為什麼 agent 特別難評估

傳統評估假設「給輸入 X，系統走路徑 Y，得到輸出 Z」；但 agent 即使起點相同，也可能走出完全不同、但都合理的路徑（有的查 3 個來源，有的查 10 個）。所以要評估「有沒有達成正確結果，且過程合理」，而不是檢查有沒有照預設步驟走 [S5]。

## 三個實務做法（S5）

1. **立刻用小樣本開始**：開發初期一個改動常常讓成功率大幅變化，所以約 20 個代表真實使用的問題就足以看出差異；不要等到有幾百題才開始評估 [S5]。
2. **LLM 當評審（LLM-as-judge）**：用一個評審提示，依量表給 0.0–1.0 分數與通過 / 不通過 [S5]。量表項目：
   - 事實正確：說法和來源一致嗎？
   - 引用正確：引用的來源真的支持該說法嗎？
   - 完整性：問的面向都涵蓋了嗎？
   - 來源品質：用的是一手來源還是低品質來源？
   - 工具效率：工具用得對、次數合理嗎？
3. **人工評估不可少**：人會發現自動評估漏掉的問題；例如早期 agent 偏好 SEO 內容農場，而不是排名較低但更權威的學術 PDF 或個人部落格，加入「來源品質」的提示規則後才改善 [S5]。

## 會改變狀態的 agent：看最終狀態

如果 agent 會修改資料（不只是查資料），每一步都會影響後面，建議評估「最終狀態是否正確」，或在幾個關鍵檢查點確認狀態，而不是逐步檢查 [S5]。

## 觀點差異：LLM 能不能當評審？

- S5：LLM 評審可以規模化地評估數百個輸出，而且單一評審提示的結果與人類判斷最一致 [S5]。
- S1：ChemCrow 案例中，LLM 評估與化學專家評估結論不同，顯示在需要深度專業的領域，LLM 可能看不出錯誤 [S1]。
- 整合：LLM 評審適合有明確量表或標準答案的情況；專業領域與邊界案例仍要靠人工評估 [整理]。
