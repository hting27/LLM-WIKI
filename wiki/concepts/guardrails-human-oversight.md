# 防護欄（Guardrails）與人類監督

## 為什麼需要？

Agent 會自己採取行動，所以要限制它「不該做的事」。防護欄幫助管理個資外洩、品牌形象等風險，但必須搭配身分驗證、權限控管等一般資安措施 [S4]。

## 多層防禦

單一防護欄通常不夠，要像洋蔥一樣疊好幾層 [S4]：

| 類型 | 作用 |
|---|---|
| 相關性分類器 | 擋掉離題的問題 |
| 安全分類器 | 偵測越獄、提示注入（prompt injection） |
| 個資（PII）過濾 | 避免輸出不必要的個人資料 |
| 內容審核 | 擋掉仇恨、騷擾、暴力等內容 |
| 工具風險分級 | 依「唯讀或可寫入、能否復原、權限、金額影響」把工具分成低 / 中 / 高風險，高風險先檢查或交給人 |
| 規則式防護 | 黑名單、長度限制、regex 等確定性規則 |
| 輸出驗證 | 確認回應符合品牌與政策 |

（表格整理自 [S4]）

建議的建置順序：先處理資料隱私與內容安全 → 依實際遇到的失敗再加新防護 → 在安全與使用體驗之間持續調整 [S4]。

## 什麼時候要交給人？

兩個主要時機 [S4]：

1. **超過失敗門檻**：例如重試多次仍無法理解使用者意圖。
2. **高風險行動**：敏感、不可逆或金額大的行動，例如取消訂單、核准大額退款、付款。

S3 也建議 agent 在檢查點或遇到阻礙時暫停等人回饋，並在沙盒中大量測試 [S3]。
